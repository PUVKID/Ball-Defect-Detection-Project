## 최신 발표·7차·LEVEL 1

| 확인 대상 | 설명 |
| --- | --- |
| 마지막 장 정리 | 발표 끝에 남는 글과 선을 줄여 감사 인사가 먼저 보이도록 정리했습니다. |
| 제거한 표시 | 질의응답이라는 글자와 아래쪽 네 파트 이름·선을 지웠습니다. |
| 보존한 요소 | 감사 인사, 발표자 이름, 학교 마크, 페이지 번호는 유지했습니다. |

발표 내용은 같은 20장입니다.

1~19장의 사진·그래프·설명과 마지막 장에서 읽는 대본도 그대로 사용합니다.

7차 PDF를 열어 마지막 장을 확인하고, 5차 대본과 질문 자료로 발표를 준비하면 됩니다.

사진에서 볼 위치를 찾는 실험 결과를 새로 만든 작업은 아닙니다.

## 최신 발표·6차·LEVEL 1

| 확인 대상 | 설명 |
| --- | --- |
| 연구 질문 | 이 연구는 사진에서 볼의 위치를 찾는 AI에 사진 손질 방법을 달리 적용해 결과를 비교했습니다. |
| 필터의 뜻 | 사진 손질 방법을 필터라고 합니다. |
| 6차 발표 목적 | 이번 6차에서는 같은 실험 결과를 발표할 때 어디까지가 배경이고 어디부터가 방법·결과인지 구분하기 쉽게 다듬었습니다. |

선으로 이어진 도식은 입력 사진이 처리되어 평가되는 순서를 보여 줍니다.

차트의 색은 필터나 계열을 눈으로 구분하는 보조 수단입니다.

색이 진하거나 새 색을 썼다고 점수가 더 높아졌다는 뜻은 아닙니다.

필터 이름·숫자·축 단위를 함께 읽으셔야합니다.

6차 발표 PDF를 먼저 읽고 5차 10분 대본의 같은 장을 따라가면 됩니다.

| 차수 | 달라진 부분 | 자료 |
| --- | --- | --- |
| 발표 자료 6차 | 파트 구분·도식 연결 선·필터 색·계열 식별 | [같은 수준 설명](../revisions/talk-6.md#user-content-reading-level-1) · [폴더](../../발표자료/6차) · [직전 비교](../revision-diffs/talk-6.md) |

## 최신 발표 자료 · LEVEL 1

| 확인 대상 | 설명 |
| --- | --- |
| 검출 대상 | 사진에서 공처럼 생긴 작은 볼의 위치를 찾는 AI를 다뤘습니다. |
| 비교한 사진 처리 | 사진을 밝게 바꾸거나, 가장자리를 강조하거나, 흐리게 하는 방법을 각각 비교합니다. |
| 필터·검출 뜻 | 필터는 사진을 손질하는 방법이고, 검출은 볼마다 네모 상자를 붙여 위치를 찾는 일입니다. |

같은 사진 손질 방법으로 AI도 다시 공부시킨 뒤 시험한 결과이므로, 이미 만들어진 AI에 아무 사진이나 넣어도 같은 점수가 나온다는 뜻은 아닙니다.

발표 PDF를 먼저 훑고, 대본의 같은 장을 읽은 다음 질문과 답변으로 확인합니다.

그래프의 높은 점수는 위치를 찾는 평가 점수입니다.

모든 사진이 완벽하게 맞았다는 뜻은 아닙니다.

Original의 Strict Acc 94.8%는 500장 중 474장에서 볼을 빠뜨리거나 더 찾는 오류가 없었다는 의미입니다.

| 발표 자료 5차 | 슬라이드 가독성·대본·질문과 답변을 함께 정리 | [같은 수준 설명](../revisions/talk-5.md#user-content-reading-level-1) · [자료](../../발표자료/5차) · [직전 비교](../revision-diffs/talk-5.md) |

<a id="guide-intro"></a>

## 프로젝트 소개

부품 사진에서 작은 볼의 상자를 찾고, 볼이 정해진 배치·개수 규칙을 만족하는지 살피는 연구입니다.

결함 위치 자체를 직접 찾는 모델은 아닙니다.

사진을 미리 처리하는 필터가 볼 검출과 영상 판정에 주는 영향을 비교합니다.


<a id="guide-problem"></a>

## 문제와 주요 기능

볼이 하나 빠지거나 엉뚱한 위치에 추가로 보이면 영상 판정이 달라질 수 있습니다.

| 볼 중심의 영역 | 정해진 개수 |
| --- | --- |
| 위 | 5 |
| 왼쪽 | 4 |
| 아래 | 2 |
| 오른쪽 | 2 |

상자를 잘 찾는 일과 사람이 판단한 불량을 맞추는 일은 같지 않습니다.

## 입력·처리·출력

### LEVEL 1 · 영상 크기와 학습·분할 조건

비슷한 사진을 공부와 시험에 나눠 넣으면 쉬운 시험이 될 수 있습니다.외부 그룹분리와 내부 검증의 중복 한계를 함께 읽으세요.

모델에 넣는 크기 1280, 한 번에 보는 8장, 최대 반복 30과 조기 종료 15는 서로 다른 설정입니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-3-row-1"></a> 영상 500장·2944×2352 | 초기에는 학습 400장·검증 100장으로 나눕니다.<br>사진 크기와 장수는 서로 다른 단위이며, 볼 상자 라벨이 별도로 필요합니다. |
| <a id="layout18-table-3-row-2"></a> 368개 근접 중복 그룹·외부 5fold | 닮은 사진이 바깥 평가의 학습/시험 양쪽에 퍼지지 않도록 그룹으로 묶어 다섯 겹 비교를 합니다.<br>그러나 내부 train/val에는 9~20개 유사 그룹 중복이 남아 결과가 낙관적일 수 있습니다. |
| <a id="layout18-table-3-row-3"></a> YOLOv8n·30epoch·입력 1280·batch8·patience15 | 입력은 모델에 넣을 크기,batch는 한 갱신에 묶는 영상 수,epoch는 전체 자료 반복 단위입니다.patience15는 개선을 기다리는 조기 종료 설정입니다.<br>최대한 도와 실제 종료를 구분합니다. |
| <a id="layout18-table-3-row-4"></a> 실험 범위 | 일반 영상은 원본 +단일 10 종 +순차 조합 5 종, 잡음비교는 원본 +단일 필터입니다.<br>조건마다 다시 학습하므로 고정 모델에 처음 보는 잡음을 넣는 외부 강건성 시험과 다릅니다. |

### LEVEL 1·상자 검출·Strict Acc·OK/NG의 차이

볼을 찾는 일과 부품이 정상인지 정하는 일은 다른 문제입니다.

상자 겹침을 보는 mAP, 모든 볼이 빠짐없이 맞아야하는 Strict, 위치별 개수를 세는 OK/NG를 따로 보세요.

세 점수의 숫자가 같아야하는 것은 아닙니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-4-row-1"></a> mAP50-95 조건 | conf0.001·NMS IoU0.7로 볼 상자 검출을 평가합니다.conf는 예측을 남길 신뢰도 문턱,NMS IoU는 겹친 예측을 정리하는 기준입니다.<br>평가 이름의 IoU 범위와 NMS 설정을 혼동하지 않습니다. |
| <a id="layout18-table-4-row-2"></a> Strict Acc 조건 | conf0.25·NMS IoU0.5입니다.<br>주석/예측 중심을 가까운 순서로 일 대 일 대응시키며 허용 거리는 주석 상자 긴 변의 0.5 배입니다.<br>볼을 모두 찾고 추가 검출도 없는 영상 비율입니다. |
| <a id="layout18-table-4-row-3"></a> 별도 OK/NG 규칙 | 중앙 부품 영역에서 위 5·왼쪽 4·아래 2·오른쪽 2개 규칙으로 판정합니다.<br>라벨 상자에도 같은 규칙을 적용한 정답과의 일치율은 전문가의 별도 불량 판정 정확도가 아닙니다. |
| <a id="layout18-table-4-row-4"></a> 평가의 기준과 보조 분석 | mAP는 상자의 겹침,Strict는 중심 대응·누락/추가, OK/NG는 개수 규칙을 평가합니다.<br>다수 클래스 기준은 불균형의 단순 기준,McNemar 는 같은 영상에 대한 두 방법의 정오답 차이를 봅니다.<br>실제 정답 CSV를 쓸 때 OKNG_CSV·REAL_LABEL_*을 확인합니다. |

### LEVEL 1 · 필터 순서와 고정 파라미터

사진을 밝게 바꾸거나 흐리게 하고 경계를 강조하면 작은볼이 다르게 보입니다.**두필터를 쓰는 순서도 결과의 조건**입니다.조합이 항상단일필터보다 좋다고 생각하지 말고 원본과 같은열의 결과를 비교하세요.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-5-row-1"></a> 단일 10 종 | Invert,Otsu,Solarize,Histogram Equalization,CLAHE,Gamma,Gaussian Blur,Sobel,Emboss,Unsharp를 원본과 비교합니다.<br>영상 밝기·분포·흐림·경계를 바꾸는 서로 다른 처리입니다. |
| <a id="layout18-table-5-row-2"></a> 조합 5 종 | Invert +CLAHE,Blur +Otsu,Sobel +Invert,HistEq +Emboss,Unsharp +Sobel입니다.<br>A +B는 A 다음 B의 순서이며 역순이나 모든 가능 조합을 시험한 것은 아닙니다. |
| <a id="layout18-table-5-row-3"></a> 비교에 고정한 설정 | CLAHE clip40·16×16 격자,Gamma0.3,Gaussian Blur σ20·121×121 커널,Emboss gain4,Unsharp amount8·σ2입니다.<br>실험에서 사용한 값이지 전 환경 최적 값은 아닙니다. |
| <a id="layout18-table-5-row-4"></a> 도구와 추가 진단 | OpenCV는 영상,PyTorch/Kornia는 필터,Ultralytics는 검출,NumPy/pandas/Matplotlib는 집계/그림을 맡습니다.<br>노트북의 볼 삭제/추가·임계값·분포·해상도·데이터 양 분석은 논문의 주 비교와 구분합니다. |

### LEVEL 1 · 저장 결과·새 학습·발표 자료의 사용법

먼저 원고와 저장 표를 읽고 필요한 경로만 선택하세요.

발표 시간 600초는 목표 배분이며 실제로 말한 시간은 리허설에서 확인해야 합니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-7-row-1"></a> 새 학습 준비 | Python/CUDA PyTorch와 영상/YOLO 라벨이 필요합니다.<br>REQUIRE_GPU =True이면 CUDA가 없을 때 중단합니다.<br>원래/root/추계 학술 대회/DataSet 경로를 실제 위치로 맞추고 train/val/test images·labels와 data.yaml을 확인합니다. |
| <a id="layout18-table-7-row-2"></a> 라벨과 출력 | 라벨 행은 class cx cy w h 이며 좌표는 0~1 정규화입니다.<br>CSV/JSON·혼동 행렬·GPU 로그를 같은 조건의 결과로 확인하고 나서 그림을 만듭니다.<br>원영상/가중치/완성 환경은 별도 준비입니다. |
| <a id="layout18-table-7-row-3"></a> 실패 확인 | CUDA 오류는 드라이버/PyTorch 장치, 경로 오류는 Linux 기본 경로, 높은 점수는 중복/불균형/정답 정의, 수치 차이는 시드/분할/가중치/캐시/필터 값, 한글 깨짐은 폰트를 확인합니다. |
| <a id="layout18-table-7-row-4"></a> 문서와 발표 이력 | 논문 1~3차는 원고 변화,4차는 검토 도구,5차는 저장 표/코드 재구성입니다.<br>발표 1차 12 본장 +3 부록·600초 →2차 20장·600초 →3차 투명 로고/자산 →4차 대본 →최종 20장 PDF/PPTX입니다.<br>슬라이드/대본 변경을 새 학습으로 세지 않습니다. |
